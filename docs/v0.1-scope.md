# v0.1 Scope

What the first version of `phase0-bootstrapper` does after the pivot, what it
deliberately leaves out, where it is weak, and where it goes next. Read it with
[`phase0-contract.md`](phase0-contract.md) (the formal contract),
[`output-schema.md`](output-schema.md) (the artifacts), and
[`safety-policy.md`](safety-policy.md) (the write rules).

## What v0.1 supports

- **State detection** on start — virgin / partial / already-bootstrapped — that
  decides whether to install the full surface, merge into what exists, or decline
  with a top-up offer (see [phase0-contract.md](phase0-contract.md)).
- **Read-only scan** via `scripts/scan.py`: a size-limited, symlink-safe walk
  that prunes caches/vendored/build dirs and prints a machine-readable
  `scan.json` — languages, top-level listing, manifests, detected commands, secret
  locations, **glossary-term candidates**, and the detected state. The sensor is
  deterministic and writes only `.ai/phase0/scan.json`.
- **Project-type detection** from structure and manifests: Python,
  Node/TypeScript, Terraform/IaC, dbt, data pipeline (notebooks), and a
  "mixed repo" label when several ecosystems coexist.
- **Command detection without execution** — npm `scripts` and Makefile targets as
  `[FACT]`; tooling inferred from `pyproject.toml` (pytest/ruff/mypy) as
  `[INFERENCE]` with confidence. **No command is ever run.**
- **Secret-file safety** — `.env`, keys, and credential files flagged by
  **existence and location only**; contents never read or printed
  (`.env.example`/`*.pub` treated as safe).
- **Bootstrap interview** — surfaces the open questions and low-confidence
  inferences to a maintainer; answers promote inferences to facts and reveal
  decisions (→ ADR) and confirmed terms (→ `CONTEXT.md`).
- **Writes the living convention surface** (see [output-schema.md](output-schema.md)):
  the `AGENTS.md` six-section skeleton + **Upkeep Contract** + **ADR-0001**
  (always — dogfood); `CONTEXT.md` and repo-specific ADRs **lazily**, only when
  the interview confirms content.
- **Managed-marker merge** — writes touch only
  `<!-- phase0:start -->…<!-- phase0:end -->`; human prose is preserved and a
  re-run is **idempotent**. A **dry-run preview + explicit consent** precedes any
  write.
- **`--no-interview` degradation** — writes the methodology half always
  (`AGENTS.md` factual + Upkeep Contract + ADR-0001) and marks repo knowledge as
  explicit "Open questions for a maintainer"; never invents `CONTEXT.md`.
- **Epistemic discipline** — claims tagged `[FACT]`/`[INFERENCE]`/`[ASSUMPTION]`/
  `[OPEN]`; confirmed claims cite inline `path:line`; the unconfirmed becomes an
  open question (see [evidence-policy.md](evidence-policy.md)).
- **Two delivery surfaces** — the Agent Skill (Claude Code + a portable copy) that
  drives the flow, and the standalone `scripts/scan.py` sensor it calls.
- **Zero runtime dependencies** for the sensor — Python standard library only.

## What v0.1 intentionally does NOT support

- **No day-N maintenance.** Day zero installs the surface and stops; upkeep is
  delegated to ecosystem skills (`grill-with-docs`, `to-prd`,
  `improve-codebase-architecture`).
- **No bespoke artifact tree.** The old 11-file `.ai/phase0/` pack is retired
  ([ADR-0001](adr/0001-adopt-living-convention-methodology.md)); the only thing
  under `.ai/phase0/` is the internal `scan.json`.
- **No remote or infra mutation.** No label/branch/PR creation, no git writes —
  day zero documents and offers consented snippets instead.
- **No LLM in the sensor.** `scripts/scan.py` is deterministic and rule-based; the
  interview and write phases are agentic (see [safety-policy.md](safety-policy.md)).
- **No deep code analysis** — no AST parsing, import graphs, or data-flow.
  Architecture surfaces as **candidate glossary terms**, explicitly low-confidence,
  for the interview to confirm.
- **No multi-context auto-split.** MVP is single-context: one root `CONTEXT.md`.
  An existing `CONTEXT-MAP.md` is respected; multiple bounded contexts are
  **suggested**, never auto-carved (that would hallucinate domain).
- **No remote repositories.** The input is a local path; cloning is out of scope.

## Known limitations

- **Command inference is heuristic** — pyproject tooling implies a convention, not
  a verified command; it stays `[INFERENCE]` until the interview or a real run
  confirms it.
- **Glossary candidates are name-based** — recurring dirs/modules, prominent
  identifiers, and README nouns are *candidates only*; the interview decides which
  are real terms ("names are not behavior").
- **Language detection is extension-based** — presence, not behavior; embedded or
  unusual languages may be missed.
- **Large/binary files are skipped** (>1 MB or NUL bytes); signals living only
  inside them are not captured and the sampling boundary is recorded.
- **Git metadata is loose-ref only** — HEAD read from `.git` files without a
  subprocess; packed refs/worktrees may yield an empty commit.
- **Single-repo, single-pass** — no monorepo-aware sub-project splitting, no
  incremental/diff mode.
- **Non-interactive runs are provisional** — `--no-interview` leaves repo
  knowledge as open questions by design, not as confident facts.

## Future roadmap (not in v0.1)

Candidate directions, roughly in priority order; none imply an LLM in the sensor
or external services unless stated.

- **Deeper, still-deterministic detection** — import graphs and real entrypoint
  detection per ecosystem (`[project.scripts]`, `__main__`, `package.json` `bin`,
  Dockerfile `CMD`/`ENTRYPOINT`).
- **Lockfile + dependency surfacing** (pinned vs. unpinned) as open questions.
- **Monorepo / multi-context awareness** — detect and *suggest* bounded contexts
  and a `CONTEXT-MAP.md`, still without auto-carving.
- **Top-up mode** maturity — richer reconciliation for already-bootstrapped repos.
- **Incremental re-bootstrap** that diffs against an existing surface and `scan.json`.
